# ERP 销售仪表盘 · 配色规范

> 适用版本：v1.2.0 起
> 诉求来源：用户「颜色还需要重新调整，主要调整颜色，你参照 ERP 业务工作台的 字体颜色来搭配处理」
> 参照实现：`@local/erp-dashboard`（ERP 业务工作台）`client.js:124-141` 的 `--e-*` 令牌块

---

## 1. 一句话原则

**本插件不再有自己的配色**，全部颜色都从 DSH 设计系统（Design System Web）取；
唯一的自定义部分，是把设计系统的别名映射成本插件历史上一直在用的语义变量名
（`--ink` / `--ink-2` / `--muted` / `--gold` / `--red` …），这样既有 ERP 业务工作台的观感，
又不破坏既有代码结构。

> 与 ERP 业务工作台完全同色板：**中性灰阶 + 近白强调色**，状态色（红/绿/橙）只用来标注状态。

## 3. 语义规则（与 ERP 业务工作台一致）

1. **文字三级**：`--ink`（主）→ `--ink-2`（次）→ `--muted`（弱化）。任何一段文字只允许落在这三档里。
2. **状态文字用原始状态色**，不做浅色变体（`.esd-b-red` 的文字就是 `#f25a5a` 本身）。
3. **状态标签三件套**：边框 = `color-mix(状态色 45%, transparent)`；文字 = 原始状态色；底 = `color-mix(状态色 12%, transparent)`。
4. **底色层级**：页面 `--navy-950` → 卡片 `--navy-900` → 表头/次级容器 `--navy-850`。
   卡片一律**实心底**（不再用半透明白叠层，避免在不同底色上发灰）。
5. **图表**：主序列 `--gold`（近白），对比序列 `--blue`，网格线 `--line-soft`。
6. **地图**：省份描边 `--line-soft`，分档填充 `--esd-geo-lv0..lv5`，标注文字 `--ink-2`。
7. **空态**：文字 `--idle`，框线 `--line-soft` 虚线。

## 4. 工程铁律（配色相关）

| # | 规则 |
| --- | --- |
| 30 | **颜色一律 `var(--令牌, #兜底)`**，禁止在 CSS/JS 里写死 rgba/hex；设计系统别名缺失时靠兜底值退化。 |
| 31 | 语义令牌必须**同时声明在 `.esd-root / .esdc-root / .esd-shell` 三个根选择器上**，否则子树里 `var()` 解析失败 → SVG 退回浏览器默认黑（历史「图表全黑」事故）。 |
| 32 | **CSS 结构必须体检**：括号配平 + 关键规则进 CSSOM。顶层一个游离的 `}` 会让 Chromium 把紧跟其后的整条规则当成「无 prelude 的块」**整条丢弃**——本轮就因此让 `.esd-root` 根容器规则（底色/布局/`color`）失效，表格单元与空态文字全部退回宿主默认黑色。体检脚本见工作区 `_preview/diag3.mjs`。 |
| 33 | 改 Client 半后必须跑 `node --check client.js` + `node selfcheck.mjs` + 预览 DOM 验收（`getComputedStyle` 断言），**不能只看截图**。 |

## 6. DSH 设计系统取值来源

```
<DSH 安装目录>/resources/app.asar
  → dsh/node_modules/@deepseek-ai/dsh-client-ui-theme/lib/client.js
```
解析 asar 头的工作区脚本：`_analysis/_asar_alias_def.mjs`（别名 → 静态色）与 `_analysis/_asar_static.mjs`（静态色 → hex）。
主题切换时别名会变，因此**插件永远只引用别名，不引用静态色**。
